PART A — HEDGE SIZING: BUY SHARES, NOT PADDED DOLLARS
================================================================================
THE MECHANIC (venue-verified, not inferred)
  A Polymarket market BUY is denominated in USDC. The venue spends the WHOLE maker
  amount and hands back amount / fill_price shares, so price improvement returns as
  EXTRA SHARES, never as a refund. Sending floor(target) x (best_ask + 2 ticks)
  worth of dollars therefore handed the entire pad back as unhedged shares:

      overshoot = 2 ticks / fill price
      +2.1% @95c   +5.6% @36c   +6.9% @29c   +20% @10c   +40% @5c

WHAT CHANGED
  The pad STAYS on the limit (it buys marketability). The SPEND is now computed
  from the price we expect to CLEAR at — the walk of the ask ladder that the
  pre-hedge gate has just done for exactly this size — and the order is sent as an
  AMOUNT, which is what the venue's own market-buy primitive takes.

    src/executor/poly_exec.py
       market_buy_spend(target_shares, expected_price) -> (usdc, expected_shares)
           usdc = floor_to_cent(target x expected_price); shares = usdc / price
       market_buy_price(price)      the whole-cent marketable ceiling (unchanged rule)
       market_buy_shortfall(price)  0.01 / price — the most the cent can leave behind
       place_market_buy(...)        now posts create_market_order(amount=...)
    src/genz/maker_rt/hedge.py      forwards the walked clearing price; the
                                    "did I get what I asked for" test now uses the
                                    venue's amount precision, not 1e-9
    src/genz/maker_rt/pregame_exec.py  passes walk_price (the gate's own re-walk)

  ONE place: pre-game and in-play share hedge_poly -> place_market_buy, so both are
  fixed by the same change. Nothing else on the trading path moved.

WHY THE AMOUNT PATH IS THE VENUE-LEGAL ONE
  The client's get_market_order_amounts does raw_maker_amt = round_down(amount, 2) —
  which IS the rule that 400'd the CSKA hedge ("the market buy orders maker amount
  supports a max accuracy of 2 decimals"). So the amount path enforces the Jul-28
  rule for us instead of us quantizing a (price, size) pair against it. The old
  quantizer is kept (its rule is still the rule) and its regression tests still pass.

HARD INVARIANTS, ASSERTED BEFORE SIGNING
  * usdc amount carries <= 2 decimals                      (property test, 20k draws)
  * expected shares <= the rest fill count                 (property test, 20k draws)
  * an order that would over-buy RAISES and is never signed (fail closed)
  * undershoot <= 0.01/price of a share — the venue's own cent, nothing more
    (0.034 sh @29c, 0.013 sh @76c). Below ~2c the cent is worth more than half a
    share; the tolerance is clamped at 0.5 so a genuinely short hedge can never
    hide inside it, and it falls through to the existing partial/unwind path.
  * sub-share dust still never reaches the venue — the dust path is unchanged.

PART C — THE SAME-CLASS BOOKING HOLE
================================================================================
  auto_flattened is the bounded sweep that closes a position the first unwind could
  not, and it books only AFTER the position reads flat — TERMINAL on exactly the same
  terms as hedge_unwound. It was reaching neither unwind_cost_today nor
  settled_pnl_exits_lifetime, so its cost would have vanished from lifetime exactly
  as the three unwinds did. It has NEVER FIRED (0 rows in every CSV ever written),
  which is precisely why it was worth closing now: nobody would have been looking.

  It now books into settled_pnl_lifetime AND settled_pnl_exits_lifetime on the same
  persist-now idempotency as hedge_unwound, and counts in the daily/lifetime unwind
  counters (which are reporting only — nothing gates on them; verified). A sweep that
  RECOVERED money books a positive, because lifetime has to move both ways or it is
  not venue truth.

  UNCHANGED, exactly as documented: the -$0.0994 of naked share dust from the three
  2026-08-02 unwinds. It is not an exit cost — it is stock the unwind could not sell
